# Java. Первая встреча 

Вариант определяется как остаток деления вашего номера в списке
на количество вариантов. Так, если мой номер в списке 6, я решаю 6 % 4 = 2 вариант. 

### Как сдавать
1. Склонируйте репозиторий
2. Переключитесь на ветку, названную согласно своей фамилии
3. Решите свой вариант (класс Main и метод main в проекте уже есть)
4. Выделите вычислительную логику решения в отдельный статический метод и напишите на него модульный тест (раздел «Тесты» ниже)
5. Запустите решение и сделайте скриншот расчета на каких-либо данных
6. Сделайте commit
7. Сделайте push
8. Откройте merge request (MR) в Github из своей ветки в ветку master. **MR назовите по своей фамилии**.
9. Дождитесь зелёной галочки CI в вашем MR — все тесты должны проходить
10. Приложите в комментарии скриншот из пункта 5 и укажите вариант.

### Вариант 1.
Напишите программу, которая вычисляет энергию, необходимую для нагрева воды.

Программа должна удовлетворять следующим требованиям:

- Пользователь вводит массу воды в килограммах, начальную и конечную температуру в градусах Цельсия.
- Программа вычисляет и отображает энергию в джоулях по формуле:

Q = M × (t_конечная − t_начальная) × 4184

где Q — энергия в джоулях, M — масса воды в килограммах,
4184 — удельная теплоёмкость воды, Дж/(кг·°C).

### Вариант 2.
Напишите программу, которая решает квадратное уравнение.

Программа должна удовлетворять следующим требованиям:

- Пользователь вводит коэффициенты a, b, c уравнения ax² + bx + c = 0 (a ≠ 0).
- Программа вычисляет дискриминант D = b² − 4ac и отображает:
  - два различных корня, если D > 0;
  - один корень, если D = 0;
  - сообщение об отсутствии действительных корней, если D < 0.

Корни находятся по формуле x = (−b ± √D) / (2a). Используйте методы из класса Math.

### Вариант 3.
Напишите программу, которая вычисляет доход по вкладу со сложным процентом.

Программа должна удовлетворять следующим требованиям:

- Пользователь вводит сумму вклада, **ежегодную** процентную ставку (в процентах) и срок вклада в годах.
- Проценты капитализируются ежемесячно.
- Программа вычисляет и отображает итоговую сумму на счёте и сумму начисленных процентов по формуле:

A = P × (1 + r/1200)^(12·t)

где A — итоговая сумма, P — сумма вклада, r — ежегодная процентная ставка
в процентах, t — срок вклада в годах.

### Вариант 4.
Напишите программу, которая вычисляет площадь треугольника по длинам его сторон.

Программа должна удовлетворять следующим требованиям:

- Пользователь вводит три стороны треугольника a, b, c.
- Программа проверяет, что из введённых отрезков можно составить треугольник:
  сумма любых двух сторон должна быть больше третьей. Если нет — выводится
  соответствующее сообщение.
- Для корректных данных программа вычисляет и отображает площадь
  по формуле Герона:

s = (a + b + c) / 2

S = √(s(s − a)(s − b)(s − c))

Используйте методы из класса Math.

### Тесты
Вычислительную часть решения оформите отдельным статическим методом: входные данные — параметры, результат — возвращаемое значение. Весь ввод-вывод (Scanner, System.out) остаётся в main. Такой метод и есть объект тестирования.

Тестовый класс создайте в `src/test/java/org/example/MainTest.java` — JUnit 5 уже подключён в `build.gradle.kts`. В проекте лежит пример для ориентира: метод `Main.greeting(...)` и тест на него (пример можно удалить, когда появится ваш собственный):

```java
// Main.java
static String greeting(String name) {
    return "Hello, " + name + "!";
}
```

```java
// src/test/java/org/example/MainTest.java
package org.example;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

public class MainTest {

    @Test
    void greetingContainsName() {
        assertEquals("Hello, Anya!", Main.greeting("Anya"));
    }
}
```

Напишите 2–3 теста на логику своего варианта, включая граничный сценарий
(отсутствие действительных корней, треугольник из отрезков не существует и т.п.).

Запуск тестов локально — `./gradlew test` (в Windows: `gradlew.bat test`),
в IDEA — зелёный значок рядом с тестом.

### Непрерывная интеграция (CI)
При каждом push и в каждом merge request GitHub автоматически собирает проект
и запускает тесты — конфигурация в `.github/workflows/gradle-build.yml`.

Результат видно по галочке рядом с коммитом и во вкладке Checks вашего MR.
MR принимается только с зелёной галочкой: если тесты упали — посмотрите лог,
исправьте и сделайте новый push.
